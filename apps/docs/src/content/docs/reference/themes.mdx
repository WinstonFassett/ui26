## Model

A **theme** is a full visual identity: palette, typography, radius, shadow vocabulary, border treatment. Light/dark is an axis **within** a theme.

State lives on `<html data-theme>` as a compound key:

| Shape | Example |
|---|---|
| `<name>` | `editorial`, `tix`, `shad` |
| `<name>-dark` | `editorial-dark`, `linear-dark` |

One dropdown picks the theme; one toggle picks light/dark/auto. Both write to `localStorage` (`ui26-theme-name`, `ui26-theme-mode`) and to the compound `data-theme` attribute pre-paint.

## Pieces

| File | Role |
|---|---|
| [`registry/themes/<name>.ts`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/registry/themes) | One file per theme. Plain data: name, label, tokens, dark overrides. The source of truth. |
| [`registry/themes.ts`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/registry/themes.ts) | Barrel. One array of imports — the only place to edit when adding/removing a theme. |
| [`registry/tokens.css`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/registry/tokens.css) | **Generated** from the barrel by `scripts/build-tokens.ts`. Don't hand-edit. |
| [`scripts/build-tokens.ts`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/scripts/build-tokens.ts) | Emits `tokens.css`. Runs on `predev` / `prebuild` / `pnpm build:tokens`. |
| [`src/components/starlight/ThemeProvider.astro`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/src/components/starlight/ThemeProvider.astro) | Pre-paint script. Reads the allowlist from the barrel at SSR; owns `window.Ui26Theme`. |
| [`src/components/starlight/ThemeSelect.astro`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/src/components/starlight/ThemeSelect.astro) | Starlight header slot — mounts the React picker. |
| [`src/components/starlight/theme-picker.tsx`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/src/components/starlight/theme-picker.tsx) | Dropdown + light/dark/auto toggle. Reads theme names + labels from the barrel. |
| [`src/pages/r/base.json.ts`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/src/pages/r/base.json.ts) | Serves the shadcn-registry `base` payload (default theme's light + dark). |
| [`astro.config.mjs`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/astro.config.mjs) | Registers the two Starlight component overrides; inlines critical `--sl-*` FOUC vars. |

Tailwind's `dark:` variant fires on any selector ending in `dark` via the custom variant in [`global.css`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/src/styles/global.css) — no per-theme wiring needed.

## Theme shape

Each theme file exports a plain object. Tokens that differ between light and dark are written as `{ light, dark }` pairs inline; tokens that are mode-invariant are plain strings. One `tokens` object is the whole truth — no separate dark-override field.

```ts
// registry/themes/<name>.ts
import type { Theme } from '../themes';

const sunset: Theme = {
  name: 'sunset',
  label: 'Sunset',
  description: 'Warm off-white, tangerine accent, no shadows.',
  tokens: {
    // Mode-invariant: plain string (emitted in light block, cascades).
    'font-sans': '"Inter", system-ui, sans-serif',
    radius: '0.5rem',

    // Mode-specific: { light, dark } pair (emitter splits across blocks).
    background: { light: 'oklch(0.98 0.02 60)', dark: 'oklch(0.14 0.04 30)' },
    foreground: { light: 'oklch(0.2 0.05 30)',  dark: 'oklch(0.96 0.02 60)' },
    // …
  },
};

export default sunset;
```

### Optional: named palette

Themes can expose a semantic palette for TS-level introspection:

```ts
const palette = {
  paper: { light: '#f6f5f1', dark: '#0e0e0f' },
  ink:   { light: '#15130f', dark: '#ececec' },
  gold:  '#e6d089',                             // mode-invariant
  // …
} as const;

const editorial: Theme = {
  name: 'editorial',
  label: 'Editorial',
  palette,
  tokens: {
    background:          palette.paper,
    foreground:          palette.ink,
    primary:             { light: palette.ink.light, dark: palette.gold },
    'primary-foreground':{ light: palette.gold,      dark: palette.ink.light },
    accent:              palette.gold,
    // …
  },
};
```

Palettes are optional (not every theme has a semantic vocabulary worth naming — brutalist's saturated primaries don't benefit). When present, the palette is exported on the Theme object so downstream code can read it directly:

```ts
import editorial from '@registry/themes/editorial';
editorial.palette?.gold;              // '#e6d089'
editorial.palette?.paper.dark;        // '#0e0e0f'
```

No CSS parsing required.

## Token contract

Every theme's light block must define (at minimum):

**Surfaces**
`--background` `--foreground` `--card` `--card-foreground` `--popover` `--popover-foreground`

**Anchors**
`--primary` `--primary-foreground` `--secondary` `--secondary-foreground` `--muted` `--muted-foreground` `--accent` `--accent-foreground`

**Feedback**
`--destructive` `--destructive-foreground` `--success` `--warn` `--info` `--purple`

**Structure**
`--border` `--border-soft` `--input` `--ring` `--radius`

**Accent companions / text tiers / code**
`--accent-ink` `--accent-soft` `--text-mute` `--code`

**Shadows** (set to `none` if the theme has none — don't omit)
`--shadow-color` `--shadow-xs` `--shadow-sm` `--shadow-md` `--shadow-lg` `--highlight-inset`

**Fonts** (only if the theme diverges from the default stack)
`--font-sans` `--font-serif` `--font-mono`

The dark block only lists tokens that change. If a value is identical to the light block (typically `--radius`, fonts, or shadow vocabulary), leave it out of `dark` — the emitter doesn't duplicate it in the generated CSS, and it cascades at runtime.

## Adding a theme

Say we're adding `sunset`.

### 1. Write the theme file

Create [`registry/themes/sunset.ts`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/registry/themes/sunset.ts) using the shape above. Fill in the full light block and the dark overrides.

### 2. Register in the barrel

In [`registry/themes.ts`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/registry/themes.ts), add one import and one array entry:

```ts
import sunset from './themes/sunset';

export const themes: readonly Theme[] = [
  editorial,
  tix,
  shad,
  linear,
  brutalist,
  sunset,
];
```

That's the only place you edit to register a theme. The pre-paint allowlist and the picker options both read from here.

### 3. (Optional) Load web fonts

If the theme uses a font not already loaded, add a `<link>` to the `head` array in [`astro.config.mjs`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/astro.config.mjs) alongside the Newsreader/Geist links.

### 4. Regenerate CSS and verify

From the docs app:

```bash
pnpm dev
```

The `predev` hook runs `scripts/build-tokens.ts` and regenerates [`registry/tokens.css`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/registry/tokens.css). Open a page, pick `Sunset` in the header dropdown, toggle light/dark/auto. Check:

- `document.documentElement.dataset.theme` flips between `sunset` and `sunset-dark`
- `getComputedStyle(document.documentElement).getPropertyValue('--background')` returns your chosen color
- Reloading the page preserves the choice
- Components on `/kitchen-sink` and `/installs` look cohesive

If a token is missing, you'll see a flash of an unrelated theme's value (the cascade falls through to the previous theme block). Any missing var = missing entry in the theme file.

## The default theme

The first entry in the barrel (`themes[0]`) is the default. Its light block doubles as `:root` in the generated CSS so documents without a `data-theme` attribute render correctly, and `src/pages/r/base.json.ts` serves it as the shadcn-registry payload. Put your preferred default first.
