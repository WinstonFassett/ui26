## Model

A **theme** is a full visual identity: palette, typography, radius, shadow vocabulary, border treatment. Light/dark is an axis **within** a theme.

State lives on `<html data-theme>` as a compound key:

| Shape | Example |
|---|---|
| `<name>` | `editorial`, `tix`, `shad` |
| `<name>-dark` | `editorial-dark`, `neon-synthwave-dark` |

One dropdown picks the theme; one toggle picks light/dark/auto. Both write to `localStorage` (`ui26-theme-name`, `ui26-theme-mode`) and to the compound `data-theme` attribute pre-paint.

## Pieces

| File | Role |
|---|---|
| [`registry/tokens.css`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/registry/tokens.css) | All token blocks. One `[data-theme="<name>"]` + one `[data-theme="<name>-dark"]` per theme. |
| [`src/components/starlight/ThemeProvider.astro`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/src/components/starlight/ThemeProvider.astro) | Pre-paint script. Owns the `THEMES` allowlist and the `window.Ui26Theme` API. |
| [`src/components/starlight/ThemeSelect.astro`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/src/components/starlight/ThemeSelect.astro) | Starlight header slot — mounts the React picker. |
| [`src/components/starlight/theme-picker.tsx`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/src/components/starlight/theme-picker.tsx) | Dropdown + light/dark/auto toggle. Owns `THEMES`, `MODES`, `LABELS`. |
| [`astro.config.mjs`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/astro.config.mjs) | Registers the two Starlight component overrides; inlines critical `--sl-*` FOUC vars. |

Tailwind's `dark:` variant fires on any selector ending in `dark` via the custom variant in [`global.css`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/src/styles/global.css) — no per-theme wiring needed.

## Token contract

Every theme block must define (at minimum):

**Surfaces**
`--background` `--foreground` `--card` `--card-foreground` `--popover` `--popover-foreground`

**Anchors**
`--primary` `--primary-foreground` `--secondary` `--secondary-foreground` `--muted` `--muted-foreground` `--accent` `--accent-foreground`

**Feedback**
`--destructive` `--destructive-foreground` `--success` `--warn` `--info` `--purple`

**Structure**
`--border` `--border-soft` `--input` `--ring` `--radius`

**Accent companions / text tiers / code**
`--accent-ink` `--accent-soft` `--text-mute` `--code`

**Shadows** (set to `none` if the theme has none — don't omit)
`--shadow-color` `--shadow-xs` `--shadow-sm` `--shadow-md` `--shadow-lg` `--highlight-inset`

**Fonts** (only if the theme diverges from the default stack)
`--font-sans` `--font-serif` `--font-mono`

The dark block can redefine only what changes. If a value is identical to the light block (typically `--radius`, fonts, or shadow vocabulary), leave it out of `-dark` — it cascades.

## Adding a theme

Say we're adding `sunset`.

### 1. Add two token blocks

In [`registry/tokens.css`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/registry/tokens.css), append:

```css
[data-theme="sunset"] {
  /* fonts, radius, shadow vocabulary, light palette */
  --font-sans: "Inter", system-ui, sans-serif;
  --font-serif: ui-serif, Georgia, serif;
  --font-mono: ui-monospace, Menlo, monospace;

  --background: oklch(0.98 0.02 60);
  --foreground: oklch(0.2 0.05 30);
  /* ...the rest of the token contract above */

  --radius: 0.5rem;

  --shadow-color: 30 20 10;
  --shadow-xs: 0 1px 1px rgb(var(--shadow-color) / 0.05);
  /* ...sm/md/lg/highlight-inset */
}

[data-theme="sunset-dark"] {
  /* only what changes for dark */
  --background: oklch(0.14 0.04 30);
  --foreground: oklch(0.96 0.02 60);
  /* ...surfaces + colors that flip; fonts/radius/shadow vocab inherit */
}
```

### 2. Register the theme in two places

In [`ThemeProvider.astro`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/src/components/starlight/ThemeProvider.astro), add the key to the `THEMES` allowlist inside the inline script:

```js
const THEMES = ['editorial', 'tix', 'shad', 'neon-synthwave', 'cyberpunk-neon', 'sunset'];
```

In [`theme-picker.tsx`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/src/components/starlight/theme-picker.tsx), add the key to the local `THEMES` array, extend the `Name` union, and add a `LABELS` entry:

```tsx
type Name = 'editorial' | 'tix' | 'shad' | 'neon-synthwave' | 'cyberpunk-neon' | 'sunset';

const THEMES: readonly Name[] = [
  'editorial', 'tix', 'shad', 'neon-synthwave', 'cyberpunk-neon', 'sunset',
];

const LABELS: Record<Name, string> = {
  /* ...existing */
  sunset: 'Sunset',
};
```

Both lists must agree. The pre-paint script uses its copy to reject unknown `localStorage` values; the picker uses its copy to render options.

### 3. (Optional) Load web fonts

If the theme uses a font not already loaded, add a `<link>` to the `head` array in [`astro.config.mjs`](https://github.com/WinstonFassett/ui26/tree/main/apps/docs/astro.config.mjs) alongside the Source Serif 4/Geist links.

### 4. Verify

From the docs app:

```bash
pnpm dev
```

Open a page, pick `Sunset` in the header dropdown, toggle light/dark/auto. Check:

- `document.documentElement.dataset.theme` flips between `sunset` and `sunset-dark`
- `getComputedStyle(document.documentElement).getPropertyValue('--background')` returns your chosen color
- Reloading the page preserves the choice
- Components on `/kitchen-sink` and `/installs` look cohesive

If a token is missing, you'll see a flash of an unrelated theme's value (the cascade falls through to the previous theme block). Any missing var = missing block entry.
