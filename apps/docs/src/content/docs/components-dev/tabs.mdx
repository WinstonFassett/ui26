React and Svelte (`tabs-machine-ui.tsx`, `tabs-machine-ui.svelte`) require a `tabs-machine.*` backend that conforms to the shared interface. The default is `tabs-machine.vanilla.ts`; swap in `tabs-machine.matchina.ts`, `tabs-machine.xstate.ts`, or any backend matching the contract. Astro (`tabs-progressive.astro`) is SSR-first — prop-driven, plain HTML, custom element for switching. No framework runtime, no hydration gap, first tab visible without JS.

## Under the hood

- **React (`tabs-machine-ui.tsx`):** `useSyncExternalStore` + `createContext` wired to whichever `tabs-machine.*` backend is installed.
- **Svelte (`tabs-machine-ui.svelte`):** `setContext` + a thin `{ subscribe }` adapter bridging the backend to the Svelte store protocol. SSR-correct with `client:load`.
- **Astro (`tabs-progressive.astro`):** prop-driven, fully SSR'd, custom element for switching. No framework runtime, no machine backend.
